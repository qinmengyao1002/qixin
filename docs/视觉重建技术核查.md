# 视觉重建技术核查 · 2026-11-05

## 原版直接证据

核查 SANSA 官方首页引用的公开脚本 https://sansatemple.com/assets/game-CHU1JbSl.js 。仅分析技术与资源清单，不复制其资产。

- Three.js WebGLRenderer、GLTFLoader、MeshStandardMaterial。
- 资源清单包含 buddha.glb、pine.glb、monk.glb、monk-remote-lod.glb、mahastamaprapta.glb、avalokitesvara.glb。
- cloth、ground、plaster、rock、roof、stone、wood 各类材质具有 color、normal、roughness 图片。
- 独立 altar-devotion.jpg 背景画与 environment/woodland.jpg 环境图片。
- 库内存在 ACES 与 Draco 接口，不足以证明游戏启用了对应选项。不能确认模型由 Blender 制作，也不能把非官方克隆当官方源码。

## 当前版本失败原因

当前 world.js 的佛像由球体、圆柱拼装，没有衣褶、手部与雕刻层级；树叶低面几何与材质相乘过暗；建筑为外立面，没有可进入的室内梁架与空间。各殿名切换主要复用同一院落；地面与屋面纹理不足。冷灰调色无法代替建模、材质和布光。

## 实施次序与验收

1. 先重建一座可进出的完整雍和宫殿：前庭只负责漫游与入口；大门附近出现进入按钮；室内有柱网、梁架、木地板、窗格、佛坛和蒲团；明确返回前庭。
2. 佛像使用原创或许可明确的精细 GLB，保持金属反射与清晰面部、衣褶。未取得合格资产前不能宣称视觉重建完成。
3. 木、瓦、石、织物应用颜色/法线/粗糙度材质；大面积旧木棕与灰石，小面积朱红与金，侧窗冷光配佛坛暖光。心静不等于压暗整个画面。
4. 实测一个殿的进出、找蒲团、跪拜、合掌、镜头不穿墙，再扩展永佑殿、法轮殿、万福阁的不同体量与陈设。
5. 院外再配置银杏、松树、花池、猫狗与乐庭；可交互处有靠近提示，装饰不冒充功能。
6. 保留自己的深绿名牌与脚下标识；选目标后靠近/转向/动作/回应；真人回应与 NPC 回礼区分。

此文件为已完成的技术核查与重建契约，尚非完成后的视觉验收报告。

## 佛像资产实测（本次截图反馈后）

读取官方公开资源的 GLB JSON 头部，未将官方模型保存或用于本项目：
https://sansatemple.com/v/37821d4f60cfb916c0bd/assets/models/buddha.glb

- 文件 1,516,016 字节，约 1.52 MB；1 个 mesh，73,294 个三角面。
- asset.generator 为 `glTF-Transform v4.5.1`，这证明最终处理工具，不证明最初建模软件。
- 材质名 `Historic gilded bronze · original scan colour`，表明制作者将它标注为历史鎏金铜雕原始扫描颜色；这不是扫描机构、作者或许可证的证据。
- 两张内嵌 JPEG：baseColorTexture 与 normalTexture；normal scale 为 0.7。
- metallicFactor 0.55、roughnessFactor 0.47、specularFactor 0.7。参数仅作分析，不能直接照搬到不同模型及灯光。
- 使用 EXT_meshopt_compression、KHR_mesh_quantization、KHR_materials_specular。

结论：质量主要由雕塑网格、表面贴图和布光共同形成；换框架或细调球体拼装无法得到这一效果。人物可以可爱，佛像需保持端正的雕塑比例，不能沿用人物的玩具造型语言。

可核实的同类资产制作案例（不是 SANSA 资产来源认定）：
https://sketchfab.com/3d-models/open-source-buddha-98fcee769d8040f8a86b9e58e60f76db
Loïc Norgeot 的 Open Source Buddha，页面注明 CC Attribution；Colmap/OpenMVS 摄影测量，Blender/BakeMyScan 从 420 万面处理到 1.5 万面，GIMP 修整纹理。尚未取得下载文件或完成造型适配验收，不能称已替换。使用时须保留署名并核对下载包许可。

工具参考：https://gltf-transform.dev/modules/functions/functions/meshopt ，https://github.com/donmccurdy/glTF-Transform 。此工具用于优化和交付，不生成精细雕塑。

下一次视觉实现的门槛：先取得许可清楚、面部/手印/衣褶完整的雕塑资产，做单佛坛光照样板并以游戏镜头截图核验；之后再扩展三尊配置与其他殿。当前已加入室内梁架和地板，但佛像仍不合格，本次研究没有完成视觉修复。

## 实施进展：扫描雕塑接入

后续优化已完成首轮真实资产替换，上述“未替换”是调研时状态：

- 坐佛：Diana Liu / Thunk3D 的 Buddha，https://sketchfab.com/3d-models/buddha-73d81e66558c4fceb23ffa57f5644cd4 。原作者 API 与模型内嵌许可均为 CC BY 4.0。57,266,136 字节源文件处理为 1,267,356 字节、186,710 三角面。
- 立像：Meta Composition Studio 的 Bronze Gilded Buddha Statue，https://sketchfab.com/3d-models/bronze-gilded-buddha-statue-be6574fd904f4e049bcb205929f862ed 。同为 CC BY 4.0。89,251,380 字节源文件处理为 2,444,472 字节、136,670 三角面。
- 从 Objaverse 公开归档获取，未复制 SANSA 资产。署名和修改说明见 public/models/credits.html，并从游戏“关于小院”链接。
- scripts/prepare-sculpture.mjs 支持重建两种模型，使用 glTF Transform、Meshoptimizer 和 Sharp。保留模型内嵌作者信息。
- 删除球体拼装佛像；GLTFLoader/MeshoptDecoder 加载新资产；按精确顶点包围盒归一化，避免旋转包围盒造成悬空；独立克隆实例资源，避免切殿后误释放缓存。
- 增加环境反射，分开殿内外光照与雾距离，封闭侧墙和顶部背景漏光；改暗木地板、织物跪垫、佛坛基座和面板。
- 人物缩至原比例 78%，名牌缩小并限制远处显示；修正衣摆换色；殿内重建导航障碍，移除不存在的树木阻挡；问好前先同步最新位置。

验证：TypeScript 检查与生产构建通过（仍有已有的大体积 JS chunk 提示）。本地 UI 已验证进入主殿、自动寻蒲团及礼拜、清和 NPC 合掌回应、切换万福阁；检查 430×860 窄屏布局并恢复浏览器尺寸。截图位于项目上层的“主殿重建-手机.png”和“主殿重建-桌面.png”。

边界：当前同一坐佛模型用于不同艺术化陈设，没有完成各殿真实供奉造像的一一对应；角色、树木和建筑仍需后续精细资产改进。不是雍和宫文物复刻，也不能视为 SANSA 全功能及全场景最终验收。此轮未发布远端。
